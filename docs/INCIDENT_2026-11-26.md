# Incident 2026-11-26: вывод `.env` в журнал сессии

## Статус

Инцидент подтверждён. Секреты не попали в Git, GitHub-репозиторий или сообщения
Telegram/Kimi. Значения были выведены в локальный журнал DSH-сессии и, как следствие,
вошли в контекст модели этой сессии.

## Первопричина

При аудите конфигурации диагностическая команда прочитала `.env` целиком и вывела строки
`KEY=value` без маскирования. Это был не сбой приложения, а ошибка процедуры аудита:
отсутствовал безопасный режим чтения конфигурации, который возвращает только имена и статус
переменных.

Усугубляющий фактор: в `.env` ещё находились не только секреты, но и неконфиденциальные
Kimi/DeepSeek base URL/model. Это увеличило объём вывода и смешало секреты с обычными
настройками.

## Где обнаружены значения

Проверка выполнялась сравнением значений без их вывода:

- текущий DSH session log:
  `~/.dsh/sessions/--home-hks-Projects-ai-supervisor--/session-.../session.v4.jsonl.zstd`;
  режим `600`; найдено 2 записи типа `tool/result`;
- защищённая резервная копия `.env` в `var/backups/config/`, режим `600`,
  каталог `700`, gitignored;
- больше нигде: не найдено в Git-истории/удалённом репозитории, `var/logs`, `/tmp`,
  shell history, `~/.dsh/storages`, `~/.dsh/llm-deepseek`, `~/.cache`.

Журнал сессии и резервные копии **не удалялись** и не изменялись без согласования владельца.

## Внешняя передача

DSH-сессия использует настроенный DeepSeek LLM endpoint (`~/.dsh/llm-deepseek`). Записи
`tool/result` входят в контекст последующих запросов к этой модели, поэтому значения могли
быть переданы DeepSeek API в рамках этой сессии. Провайдерские журналы и срок хранения
контролируются политикой провайдера.

Нет признаков передачи значений:

- Kimi API;
- OpenAI API;
- OpenAI-compatible endpoint;
- GitHub API или Git remote;
- Telegram Bot API;
- DeepSeek Harness worker-процессам.

GitHub publication после инцидента не содержала `.env`/`config.toml`; история Git была
очищена от локального `config.toml`.

## Выполненные исправления

1. Добавлен `ai-supervisor config-audit`: печатает только пути, режимы, имена переменных,
   статусы `set`/`empty`, роли и наличие credentials; значения не читает в вывод.
2. `SecretRedactor.from_settings` теперь включает `GITHUB_TOKEN` (ранее он не попадал в
   явный список).
3. `RedactionFilter` маскирует сообщение, аргументы, `stack_info` и exception text перед
   записью в stderr/file handler.
4. `ConversationService.add_message` и `messages_for_api` очищают пользовательские сообщения
   и preserved reasoning до сохранения/отправки модели.
5. Project/conversation/worker prompts, plan/review/classify промпты и memory context
   проходят через `SecretRedactor`.
6. `.env` оставляет только credentials/personal identifiers; несекретные base URL/model
   перенесены в `config.toml`.
7. В репозитории нет `.env`, `config.toml`, `var/`; Git-история не содержит `config.toml`.
8. Добавлены `scripts/audit_secrets.py` (сканирует файлы по значениям, печатает только пути и
   имена ключей) и `ai-supervisor config-audit`.
9. Добавлены регрессионные тесты на redaction, safe env reading, config-audit, log filter и
   контекст модели: **125 passed, 4 skipped**.

## Остаточный риск и необходимые действия

Старые значения остаются в локальном DSH session log до согласованного удаления/архивации
и могут оставаться в журналах DeepSeek-провайдера по его политике. Поэтому необходимо
ротировать:

- `TELEGRAM_BOT_TOKEN`;
- `KIMI_API_KEY`;
- `DEEPSEEK_API_KEY`;
- `GITHUB_TOKEN`.

После ротации обновить `.env`, сохранить режим `600`, перезапустить сервис и выполнить:

```bash
ai-supervisor config-audit
ai-supervisor doctor
```

Не удалять session logs/backups автоматически: решение об удалении принимает владелец.
